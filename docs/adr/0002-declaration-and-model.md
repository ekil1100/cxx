# ADR-0002：单次声明、延迟包绑定与不可变项目模型

包要求来自执行 `build.cpp`，而导出 Target 又依赖包解析；若声明 Interface 立即要求包已安装，首次构建会形成循环。建议 `build()` 单次执行只收集声明，`dependency` 返回稳定逻辑句柄，随后解析包元数据、绑定导出 Target 并冻结 Project Model，再降低为 Action Graph。

## 比较的方案

- 反复执行脚本直到依赖收敛：任意 C++ 副作用与条件变化可能不收敛，也难保证稳定解析。
- 声明阶段同步下载与构建包：将配置与执行混合，使 validate/dry-run 及故障事务难以解释。
- 单次声明与延迟绑定：限制声明阶段读取已解析包文件，但阶段清晰，建议采用。

## 影响与待确认

Registry 元数据需在包构建前提供依赖，recipe 实际声明须与其一致。暂不允许依赖解析后的包内容决定新增要求；未来需要独立的受约束 Interface，而非隐式重跑。

Builder 持有运行期 Handle，冻结模型拥有全部值对象，持久化通过显式 DTO 与语义 ID。Target Graph 表达使用和链接关系，Action Graph 表达执行关系。任意脚本输入不可追踪时默认重新执行声明，只有可验证封闭配置输入才自动复用模型。

验收：P02、T08/T12/T29。依据 [PRD §5、§8、§13.1](../../CXX_PRD_v1.0.md)；详细模型见[架构 §5–6](../../CXX_ARCHITECTURE_v1.0.md)。
