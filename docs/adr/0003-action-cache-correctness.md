# ADR-0003：完整依赖身份优先于缓存命中率

历史 depfile 只能证明上一轮读过哪些文件，无法发现新出现的高优先级同名头文件或 `__has_include` 条件变化。建议在 Compile 缓存查询前取得有效依赖扫描结果，并将工具闭包、路径语义、SDK、参数、环境及完整输入内容纳入规范 Key；无法证明封闭输入时禁用共享缓存。

## 比较的方案

- 按命令和旧 depfile 查询：代价低，但存在可构造的错误命中。
- 全量重新扫描：正确性容易验证，适合作为 V0 基线；空构建仍可做到零 Compile/Link。
- 可验证扫描缓存：追踪搜索顺序、目录成员和缺失候选后逐步优化；覆盖不足继续扫描。

## 影响与待确认

建议使用 SHA-256 的不可变 CAS，Action Cache 与 Package/Toolchain 身份层分开。跨项目缓存只对已经证明路径映射安全的配置启用根路径归一化，其他配置保留真实路径身份。生成输入必须先就绪再扫描，BMI/PCH 采用完整编译配置身份。

无安全沙箱时，声明输入与可信工具是共享缓存前提，不能声称强制阻止工具读取其他输入。执行期间观察到输入变化的结果不发布。远程对象摘要校验只证明完整性，写入者信任由服务配置和 Namespace 授权建立。

验收：P03/P05、T19/T20/T28/T32；包括头文件遮蔽、缺失变存在、同 mtime 修改、路径差异和损坏对象。依据 [PRD §6.3、§7.3](../../CXX_PRD_v1.0.md) 与[架构 §7–8](../../CXX_ARCHITECTURE_v1.0.md)。
