# ADR-0004：单 Lock、多解析域与独立协议版本

PRD 要求工具链与包共用一个 Lock，且普通构建不得悄悄升级。建议采用确定性排序 JSON，将不同平台、Profile 和 Host/Target 角色的解析集合存入同一 `cxx.lock`，通过完整候选校验和原子替换提交；未知主版本明确拒绝，严格锁定模式不迁移或写入。

## 比较的方案

- 每平台独立 Lock：容易分离平台差异，但偏离单 Lock 的产品目标。
- 一个平面全局解析：难以表示条件依赖、Host 生成器和异构 Target。
- 单文件多解析集合：保留统一审阅入口并表达配置差异，建议采用；需清晰显示各集合的声明身份和变更原因。

## 影响与待确认

Lock 中保存精确来源与内容身份，不保存凭据和本机安装绝对路径。新增解析集合不升级旧集合；定向更新仅放开指定项及必要依赖闭包。工具链与包分阶段解析但整体提交，失败不得留下部分有效文件。

Edition、Query Schema、Lock Format 和 Native Cache Protocol 独立版本化；CLI 版本不作为项目常规构建身份。工具链安装可能先于 Lock 提交，失败后保留已验证的全局对象；项目编译失败也不撤销已经合法提交的解析结果。

JSON 格式、解析集合键与迁移细节需在 M2/M3 冻结。验收：P02、T14/T15/T32。依据 [PRD §4.4、§5.3、§13.7](../../CXX_PRD_v1.0.md) 与[架构 §6.4](../../CXX_ARCHITECTURE_v1.0.md)。
